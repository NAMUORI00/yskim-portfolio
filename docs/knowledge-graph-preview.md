# 오른쪽 지식 그래프 시안 — 층위형 2.5D 지식 지도

로컬 검토용 미리보기입니다. 공개 홈(`/`)과 지금의 그래프는 바뀌지 않습니다.

- 주소: `/design/knowledge-graph` (noindex). 실제 홈 화면에 최신 콘텐츠·글꼴·섹션 순서 그대로, 오른쪽 레일(과 휴대폰 서랍)만 시안으로 바꿔 보여 줍니다.
- 아래 가운데의 전환 단추로 기존/제안을 비교합니다. `?graph=original`이면 기존 그래프로 열립니다.

## 1. 지금 그래프의 문제

- 프로필을 중심으로 프로젝트·연구·기술·관심 저장소 약 50개 노드를 한 화면 원형 궤도에 모두 그립니다. 궤도는 계속 돌고, 이름은 가리킨 노드에만 8px로 나오며 레일이 좁아지면 더 작아집니다.
- 관심 저장소(GitHub 스타)가 프로필에 이어져 전문성처럼 보이고, 선이 "왜" 이어졌는지(근거인지, 같은 단어인지) 읽히지 않습니다.

## 2. 두 방향

| | A. 층위형 2.5D 지식 지도 (선택) | B. 경량 3D 성좌 |
|---|---|---|
| 메타포 | 겹친 판 세 장: 연구 질문 → 프로젝트 → 기술 | 구 껍질 위 노드, 끌어서 회전 |
| 읽기 | 자리가 고정되어 공간 기억이 남음. 층 = 범주, 수직선 = 근거 | 돌릴 때마다 자리와 이름표가 바뀜 |
| 좁은 레일 | 세로로 긴 레일에 맞고 이름표가 늘 수평 | 작은 공 안에 점이 몰려 지금과 비슷한 인상 |
| 움직임 | 처음 한 번 펼침, 고른 경로만 떠오름 | 회전이 핵심이라 움직임이 많음 |
| 키보드·대체 | ←→ 같은 층, ↑↓ 위아래 층. 목록과 1:1 | 3D 이동을 키보드로 옮기기 어려움 |
| 비용 | SVG + HTML, 의존성 추가 없음 | 이름표 충돌·정렬 처리가 많고, 실제 3D면 three.js급 의존성 |

A를 고르고, B의 장점(입체감·각도 조작)은 "넓게 보기"의 각도 조절로 일부 가져왔습니다.

## 3. 선택한 메타포 — 지층 지도

- 축측 투영(회전·기울기, 원근 없음)으로 세 판을 겹칩니다. 원근이 없어 층 사이 선이 늘 수직입니다.
- 세 판이 바닥 평면 하나를 함께 씁니다. 연구 질문 바로 아래에 그 질문의 프로젝트, 그 아래에 프로젝트의 기술을 놓아 같은 영역이 같은 주제가 됩니다.
  - 왼쪽: 문서 검색·센서 운영 → 스마트팜 RAG·항공우주 RAG → RAG·Qdrant·FastAPI
  - 가운데: 영상 QA → MV-EviRAG → LoRA·PyTorch / 개발 자동화 → AI 교차 리뷰·MediaMTX 설치 → PowerShell·Shell
  - 오른쪽: 로컬 AI·음원 분리 → 분리 모델 학습·음원 분리 웹 → CUDA·Spleeter·Spring
  - 여러 프로젝트가 함께 쓴 Python은 기술 판 가운데에 놓입니다.
  - 연구 질문과 직접 이어지지 않은 프로젝트 10개는 프로젝트 판 앞쪽 띠에 사용 기술이 겹치는 것끼리 나란히 둡니다(예: Arduino 프로젝트 3개).
- 깊이 단서: 평행사변형 판과 옆면 두께, 판 격자, 고른 경로의 노드가 기둥과 그림자를 남기며 떠오르고 나머지는 흐려집니다.
- 색은 포레스트 그린 하나에 투명도만 달리 씁니다. 층은 모양으로도 구분합니다(● 연구 질문, ○ 프로젝트, ◆ 기술).

## 4. 연결 규칙 — 콘텐츠에 적힌 것만

- 연구 → 프로젝트: 연구 본문의 '관련 프로젝트' 링크, 그리고 연구 설명에 직접 적힌 프로젝트(문구 기준. 문구가 사라지면 연결도 빠지며 테스트로 확인).
- 프로젝트 → 기술: 프로젝트 태그 가운데 기술 스택(`skills.json`)에 있는 것만. 스택에만 있고 프로젝트 근거가 없는 기술(예: Docker)과 스택에 없는 태그(예: Hydra)는 넣지 않습니다.
- 관심 오픈소스는 직접 한 작업의 근거가 아니므로 제외합니다. 숙련도·점수는 만들지 않습니다. 기술 설명의 "프로젝트 N개에서 사용"은 이 포트폴리오에 실린 사실입니다.
- 현재 콘텐츠 기준: 연구 질문 6 · 프로젝트 17 · 기술 29, 연결 55.

## 5. 상호작용

- 기본 상태: 연구 질문 이름만 보이고 선은 없습니다. 읽는 섹션에 맞춰 해당 판이 살짝 진해집니다(프로젝트 섹션은 대표 작업 3개, 기술 스택 섹션은 3개 이상 프로젝트가 쓴 기술 이름).
- 가리키기·키보드 초점·홈 목록에서 프로젝트 가리키기(또는 넓게 보기 대화상자 열기) → 그 경로만 떠올라 이어집니다. 우선순위는 가리킴 → 키보드 → 홈 목록 → 고정입니다.
- 클릭·Enter로 고정, 다시 누르기·Esc·빈 곳 클릭으로 풉니다.
- 설명 칸: 전체 이름, 한 줄 성과(`metric`), 위·아래 층 칩(누르면 그 노드를 고정), "…에서 보기"(본문의 프로젝트 행·연구 카드·기술 항목으로 옮겨 잠깐 테두리 표시).
- 키보드: Tab 한 번으로 진입(roving tabindex), ←→ 같은 층, ↑↓ 이어진 위·아래 층, Home/End, Enter/Space 고정, Esc 해제.
- 넓게 보기(대화상자): 기울여 보기 · 정면 보기 · 목록. 끌기·Shift+화살표·회전 단추로 각도를 바꿉니다(좌우 약 ±35°). 프로젝트 이름까지 보입니다. Esc는 고정을 먼저 풀고 그다음 창을 닫으며, 닫으면 연 단추로 초점이 돌아갑니다.
- 휴대폰(768px 이하) 서랍: 작은 미리보기와 "지식 지도 열기"(전체 화면 넓게 보기).

## 6. 움직임과 접근성

- 처음 한 번 판이 펼쳐지고(0.7초), 고르면 경로가 떠오르며 선이 이어집니다(0.2–0.34초). 반복 애니메이션과 자동 회전은 없습니다.
- 움직임 줄이기 설정에서는 펼침·각도 전환·선 그리기를 모두 생략합니다.
- 이름표는 1px 좌표의 HTML 글자(레일 12·11px, 가장 좁은 레일에서만 연구 이름 11px)라 레일 폭에 따라 줄지 않습니다. 겹치면 배치 알고리즘이 비키고, 자리가 없을 때만 이름표를 숨기며 점과 설명 칸 목록은 남습니다.
- 다크/라이트와 한국어/영어를 따릅니다. 노드 id는 원본 기준이라 언어를 바꿔도 같은 자리에 있습니다.
- 대체 화면: 시안에서 오류가 나면 그 자리만 기존 그래프로 돌아갑니다. 넓게 보기의 목록 보기와 고정 알림(화면 낭독기)이 같은 내용을 글로 줍니다.

## 7. 충실도 한계

- 진짜 3D가 아닌 축측 2.5D입니다(원근·조명 없음). 레일은 각도가 고정이고, 각도 조절은 넓게 보기에서만 합니다.
- 짧은 이름, 연구 질문 배치 순서, 설명에 적힌 프로젝트 연결은 편집 레이어(`knowledgeMapModel.ts`)에 있습니다. 적용한다면 프로젝트·연구 frontmatter(예: `shortLabel`, `relatedProjects`)로 옮기는 편이 관리에 낫습니다.
- 이름표 폭은 글자 종류로 어림합니다(실측 아님). 가장 붐비는 경우(음원 분리 웹의 Spring 기술 묶음, Python을 쓴 프로젝트 8개)에는 레일에서 이름표 일부가 숨겨집니다. 점은 표시되고 설명 칸과 넓게 보기에는 모두 나옵니다.
- 769–1180px 너비에서는 지금처럼 레일을 숨깁니다(서랍도 없음). 적용 시 사이드바 진입 단추를 검토합니다.
- 미리보기용 연결 방식: `HomeView`의 `renderKnowledgeGraph`(미리보기 전용, 공개 홈은 넘기지 않음)와 지연 로딩 라우트. 시안 코드는 공개 홈 번들에 들어가지 않습니다.
