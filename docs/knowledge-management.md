# 포트폴리오와 지식 맵 관리

## 한 번 입력하는 위치

- 프로젝트: `content/projects/<slug>.mdx`의 본문과 `knowledge` 항목
- 연구: `content/research/<slug>.mdx`의 본문과 `knowledge` 항목
- 논문·경력: `content/education.json`의 해당 항목. `id`는 이름을 바꿔도 유지합니다.
- 공통 지식 정의: `content/knowledge/catalog.json`. ID, 분야, 한·영 이름, 정의만 관리합니다. 수행 내용은 여기에 쓰지 않습니다.
- 코드·시뮬레이터 등 보충 근거: `content/knowledge/supplemental.json`. 관련 프로젝트가 비공개이면 그 주소에 연결된 보충 근거도 공개 맵에서 제외합니다.

3D 전체 보기와 2.5D 상세는 같은 지식 ID와 관계를 사용합니다. 기술 스택도 동일한 공개 근거에서 생성합니다. `content/skills.json`은 기존 그룹 순서와 배치 및 팀 활동 항목의 템플릿입니다. 여기에 기술을 추가하는 것만으로 구현 경험이 생기지 않습니다.

## 기존 지식을 프로젝트에 연결

MDX의 앞부분에 JSON 한 줄로 입력합니다. 본문의 실제 문장을 `quote`에 사용합니다.

```yaml
knowledge: {"claims":[{"node":"qdrant","mode":"built","quote":"본문에 실제로 적은 수행 내용"}],"relations":[]}
```

`built`는 구현·참여, `studied`는 연구·실험, `interest`는 관심 주제, `listed`는 목록에만 적힌 항목입니다. 구현과 관심을 구분합니다. 관계는 `from`, `to`, `relation`, `quote`로 같은 작업에 기록합니다. `uses`, `implements`, `applies`, `supports`, `prerequisite`만 사용하며, 단순히 같은 프로젝트에 등장했다고 관계를 만들지 않습니다.

새로운 기술은 공통 사전에 한 번 등록하고 해당 작업에 연결합니다. 프로젝트를 추가할 때는 지식 연결도 함께 작성합니다. 공개 프로젝트에 지식 연결이 없으면 검사가 실패합니다. AI가 글에서 추측한 기술을 자동으로 구현 경험으로 승격시키지 않습니다.

## 변경과 공개 상태

- 이름·정의 변경: 공통 사전 한 곳을 수정하면 두 맵과 기술 스택에 반영됩니다.
- 실제 수행 내용 변경: 작업 본문과 해당 근거 인용을 수정합니다. 인용이 본문과 달라지면 빌드가 실패합니다.
- 작업을 `draft` 또는 `archived`로 변경: 해당 출처의 주장과 관계가 제외됩니다. 다른 공개 근거가 없다면 노드와 기술 스택 항목도 사라집니다.
- 논문 제목·상태 변경: 이력 항목을 수정합니다. 맵에서 고정 문구를 따로 작성하지 않습니다.
- `private: true`는 비공개 **저장소** 표시입니다. 공개 포트폴리오 소개를 숨기려면 `status`를 변경합니다.

## 검사와 배포

- `pnpm knowledge:audit`: `docs/knowledge-audit.json`에 현재 집계·출처·아직 분류하지 않은 태그 후보를 기록합니다.
- `pnpm validate:knowledge`: 원문 인용, 없는 ID, 중복 관계, 공개 상태 전파를 검사합니다.
- `pnpm check`, `pnpm test`, `pnpm build`: 전체 검증입니다.

`pnpm build`가 지식 검사를 먼저 실행하므로 GitHub CI뿐 아니라 Cloudflare의 직접 Git 빌드도 불일치가 있으면 실패합니다. 변경 후 Git push를 해야 공개 사이트가 갱신됩니다. 이번 작업은 로컬 적용이며 자동으로 push하지 않습니다.

현재 보존된 근거에는 코드·시뮬레이터 기록도 있습니다. 이는 실측 운영 성과나 실제 농장 자율 제어를 의미하지 않습니다. 영문 화면에서 번역되지 않은 근거 인용은 원문 그대로 표시됩니다.

## 영문 번역의 최신성

`content/i18n/source-revisions.json`은 번역을 검토한 당시의 원문 지문입니다. 프로젝트·연구·이력 원문이 달라지면 예전 번역을 덮어쓰지 않고 최신 원문으로 돌아갑니다. 번역을 실제로 검토·수정한 항목만 새 지문으로 갱신해야 합니다. 원문을 바꿨다는 이유만으로 모든 지문을 갱신하면 안 됩니다.
